# Grasp V1

Spaced-repetition flashcards generated from your own Obsidian notes (synced to
Dropbox), reviewed on an FSRS schedule. This file records what V1 is, how it
behaves, and how to build and install it.

## What V1 does

| Area | Behavior |
|---|---|
| Sign in | Supabase email/password. Each account sees only its own data (row-level security). |
| Notes | Reads `/Applications/remotely-save/Knowledge/6 - Main Notes` (subfolders included). Only notes containing `#flashcard` are used. |
| Generation | Groq `openai/gpt-oss-120b` via the `llm` Supabase Edge Function (keys never ship in the app). A pass adds exactly the "Cards per pass" count (default 15). |
| Vet tab | Every generated card is swiped first: accept, discard, or edit then accept. Only accepted cards enter sessions. |
| Session tab | Due reviews plus up to "New cards per day" (default 10) new cards. If fewer are ready than a full session, it shows "N of M ready" with a "Start with N now" option. |
| Retention tab | Recall strength by card type, concept gaps, review streak grid, remake pile. |
| Explore tab | Adjacent concepts and cited web cards (Tavily via the `search` Edge Function). Loads only when the tab is first opened. |
| Reminder | Optional daily notification, set in Settings. |

## How generation works

1. **When it runs:** on a brand-new account (first batch), on app open only when
   nothing is waiting in Vet and fewer than a day's worth of approved new cards
   remain, or manually from Settings, "Generate cards now".
2. **Which notes:** the pass lists file names (no downloads), then downloads in
   rotation order, least recently visited first, until it has 10 tagged notes
   (`Config.notesScannedPerPass`). Untagged notes are stamped as visited so they
   rotate to the back and are re-checked once per lap.
3. **No duplicates:** each note's existing card questions (newest 50, any
   status, including discarded) are sent to the model as "already covered".
   Exact repeats are also filtered in code.
4. **Bounded:** at most "Cards per pass" LLM calls per pass. A note with nothing
   new left returns no cards and moves to the back.
5. **Type mix:** starts even across anchor / mechanism / application, then
   leans toward the types you like and away from those you flag. Settings shows
   the live mix.

## Rate limits (Groq)

- Per-minute limits (TPM/RPM): the app waits as long as Groq says, then retries.
- Daily limits (TPD/RPD): fail immediately with "Rate limited by Groq".
- The `llm` function picks a random key first and falls back to the other on 429.
- `reasoning_effort: "low"` keeps hidden reasoning tokens down.
- Groq limits are per organization: `GROQ_API_KEY_2` only adds capacity if it
  comes from a different Groq account.

## Build and install on the phone (R8YY80GL0FY)

Run from the project root in PowerShell. `adb` is not on PATH on this machine,
so it is called by its full path.

1. **Plug in the phone**, unlock it, set USB mode to **File transfer**, and
   accept the "Allow USB debugging?" prompt (tick "Always allow").
2. **Confirm it is connected:**
   ```powershell
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
   ```
   You should see `R8YY80GL0FY    device`. If it says `unauthorized`, accept the
   prompt on the phone; if it is missing, replug and check USB debugging.
3. **Build the release APK** (about 3 to 5 minutes):
   ```powershell
   flutter build apk --release
   ```
   Output: `build\app\outputs\flutter-apk\app-release.apk`
4. **Install it on the phone** (`-r` updates the existing app and keeps its data):
   ```powershell
   & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" -s R8YY80GL0FY install -r build\app\outputs\flutter-apk\app-release.apk
   ```
   `Success` means done. Unplug; the app needs no computer afterwards.

**Shortcut** (build + install in one step, then quit with `q`):
```powershell
flutter run --release -d R8YY80GL0FY
```

**No cable:** copy `app-release.apk` to the phone (Drive, USB, etc.), open it,
and allow "install unknown apps" when asked.

**Signing:** there is no `android/key.properties`, so release builds use the
debug key. Updates install over each other as long as they are built on this
machine. If Android reports a signature conflict, uninstall the old app first
(cards are safe in Supabase; Dropbox login and settings are on the phone and
must be redone).

## Known limits

- Renaming or moving a note resets its rotation and duplicate memory (keyed by path).
- Reworded duplicates can slip past; the code only filters exact repeats.
- The duplicate list shows the model the newest 50 cards per note.
- Changing "New cards per day" or the session cap mid-review restarts the review.
- Connecting Dropbox downloads every note once to count tagged notes.
- The remake pile regenerates with a fixed even type mix.
